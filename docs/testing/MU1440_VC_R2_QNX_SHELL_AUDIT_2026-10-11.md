# MU1440 VC R2 QNX shell audit (2026-10-11)

Source of truth: [MU1440_QNX_SHELL_COMPATIBILITY.md](MU1440_QNX_SHELL_COMPATIBILITY.md) and observed operator transcript. **External `printf` and `cmp` are absent.** The audited R3 test ZIP incorrectly included `printf` in both `vc_r2_unit.sh` and `vc_r2_capture.sh`. This was a package regression, not a new HMI/DSI fault.

Observed precise failure: `prepare` created `vc-r2-state/original/`, `staged/` and an empty `hash-tool` when redirection occurred; external `printf` failed before OEM backup or any write to `/mnt/app`. It is incorrect to claim that no state folder was created. The documented SD hash helper is the sibling `/net/mmx/fs/sda0/esd/carplay-test/sha256sum-run143`, referenced via `../sha256sum-run143` from `vc-dual-r2/`; `../payload/sha256sum` is the second project-provided candidate. No new helper binary is needed.

R4 private test-kit package `MU1440_VC_R2_TESTKIT_QNX_AUDITED_R4.zip`, SHA-256 `a03abcb208546dbb045abbfae7321ae495a8cef5a2c64674fb0ba10438f40004`. The flat package includes the two unchanged CI-verified QNX ARM listener executables, corrected `vc_r2_unit.sh` (SHA-256 `651718fa836764493c49efed2b1adee2e3d259fae213e9a553f9ee2e97bce1f1`), corrected `vc_r2_capture.sh` (SHA-256 `d15a5719cfbb81e7d2a03b5a64f2e9bb86c31bd0a8bc87e5f7b348e9ab10672a`), and updated README. Only the corrected capture script is currently present in this PR's source diff; the exact unit-controller file is supplied by the package, **not yet repository-synchronized**.

Audit results: both external `printf` calls replaced by shell `echo`; diagnostic `awk` uses `print`; no external `cmp`, `sed`, `tr` or firmware-default hash requirement; executable helper path grounded in actual vehicle directory listing. Hashing now checks the hash helper's exit code rather than masking it via a pipe into `awk`. `prepare` supports resuming an incomplete own state with no `PREPARED` marker (including an empty `hash-tool`), while activation still requires a complete backup. Runtime mount ownership restored by an exit trap, keeping `/mnt/app` remounting limited to activation/restoration. `cp -p` is supported in QNX 6.5 official utilities reference.

Verification: shell syntax checks; static no-external-printf scan of both scripts; offline mock-unit regression with precisely the observed partial state and `status -> prepare -> activate -> restore -> status`, including both OEM fixtures byte-identical before/after and unchanged unrelated lines; ZIP CRC and bundled SHA-256 manifest verified. This is a **host simulation**, not on-unit confirmation. For the actual unit, replace both shell scripts only and run **`/bin/ksh ./vc_r2_unit.sh prepare`** once. Do not delete `vc-r2-state/` and do not run activation until prepare reports PASS.
