# A2.3 persistent access / migration evidence ledger

**Evidence level: host/source-derived; migration NOT qualified.** This is a product storage contract review for the three-profile beta. It is not an installer, a snapshot of an MMX unit, a current live setting report, or permission to write to target storage.

## Consolidated graph, not competing setting registries

The single machine-readable graph is generated by:

\`\`\`bash
python3 tools/release/storage_access_graph.py --self-test --json-out storage-access-graph.json
\`\`\`

It reads the **existing** source defaults inventory, broker C↔Java crosscheck, path triage and six high-risk marker contracts rather than creating a second setting authority. The source-to-path graph records **66 candidate persistent path rows** at the pinned source review: 13 CarPlay registry groups containing 48 keys, 13 broker-owned CAS/revision switch files, and 40 additional legacy/config/backup/receipt/path candidates. It independently records eight navigation-script \`ROOT + filename\` compositions, two external start-hook restoration paths, 18 nonliteral source leads, and excluded volatile/script/directory fragments. These numbers are source findings, not confirmed file counts on a particular vehicle.

Every record includes its exact current-path candidate, source-classification confidence, source evidence, a candidate logical owner or investigation category, and an **unset final destination**. All final reader/writer, format-conversion, boot-consumer, upgrade/uninstall and rollback checks remain false by default. \`--require-complete\` rejects the current graph. Never promote a lexical hit from source/test/docs into an authoritative writer or actual installed file.

## Distinctions that must survive migration

| Scope | Source-backed current semantics | What must be proven before moving it |
| --- | --- | --- |
| 13 CarPlay groups | \`settings/registry.json\` canonical group basenames; \`alt111_settings_paths\` joins dynamic \`/tmp\` and \`/mnt/app/root\` prefixes; values use temp/persistent/profile/compiled precedence. Persistent writes currently policy-blocked in the helper. | Every actual GEN2/broker/CLI/legacy binary consumer and format parser; coordinated cutover and restoration of user values. The group \`mibr-carplay-autodirect\` is a registry value, **distinct from** the old presence flag \`mibr-carplay-autodirect.enabled\`. |
| 13 broker switches | Broker C \`mibr_switch_set()\` owns guarded writes; Java \`MibrDurableSwitch\` reads revisioned magic/CAS files. | All secondary readers, conditional writers, existing revisions, default overrides, race/idempotence, and exact format-preserving migration. Do not flatten magic/revision to generic \`enabled=1\`. |
| Legacy navigation shell values | \`gen2_nav_config.sh\` and \`gen2_safearea.sh\` construct eight filenames from \`ROOT=/mnt/app/root\`, including nav query, surface, ETA, speed, compass, maneuver and SafeArea. | Their own per-file parsers, binary readers, relation to registry \`mibr-carplay111-nav.conf\`, and uninstall. The old names are not automatically aliases for the modern group. |
| Boot/activation controls | Auto-Direct uses file **presence** in generated \`lsd.sh\`; parity drive uses content \`1\`/\`0\`; isoTX2 uses **absence-is-enabled**, with its path embedded in stock-\`startup.sh\` integration. Broker durable permission requires exactly two bytes \`1\n\`. D2 also bridges persistent presence to a volatile legacy marker. | Joint rewrite of actual installed hook, script/template, reader, writer, rollback and early-stock-start branches. A filename suffix does not determine format or polarity. |
| Native menu and profile | \`mibr-menu.conf\` uses menu-owned validation/CRC, not the broker CAS format; \`mibr-platform-defaults.conf\` is a platform override, not a user choice. CPVC profile and display scaling have QNX mount/lease/recovery gates. | One original format per owner, no second active persistent store, no accidental profile/default overwrite, exact CRC/lease/readback and RO restoration. |
| Vehicle/other modes | \`vdata.mode\`, \`vstatus.mode\`, calibration and menu-language paths have firmware-/module-specific readers and value contracts. | Source/ABI-compatible HMI and native consumers and permitted/unsupported values on all three exact firmware profiles. |
| Receipts, backup and uninstall | \`mibr-kit/\` version receipt, deployment ownership flags and stock backups/restore files are recorded as separate non-preference candidates. | Preserve exact original bytes, metadata, checksum and foreign patch ownership; do not sweep these into \`config/features\` or delete during defaults reset. |
| \`/tmp/mibr-*\` and runtime paths | Volatile IPC, status, PID, lock and session files are distinct from durable configuration. System launch files outside \`/mnt/app/root/altscreen-u2\` require own backup/restore. | Keep QNX shmem-compatible transient protocols; preserve installed executable and boot timing/paths until a separately qualified coordinated release. |

## Exact remaining acceptance before any runtime migration

1. Close all 66 candidate entries and any newly discovered source/firmware paths: identify the **one authoritative writer** (or explicitly owner-blocked persistent write), all actual C/Java/shell/compiled-Binary readers, parser/grammar, format version, key/default/priority, and live activation boundary. A file path is not a setting identity.
2. Audit scripts that *generate* actual on-unit \`lsd.sh\` and \`startup.sh\` byte changes, startup checks without SD, rollback preimages, installation/upgrade/uninstall entrypoints and early boot OEM stock recovery.
3. Keep literal links to current configuration separate from volatile environment/search paths and paths only documented in tests. Validate cross-module and brand-specific consumers for \`skoda-mu1440-p4526\`, \`seat-mu1409-p4708\` and \`seat-mu1447-p4709\`; absence of source/ABI proof is a blocker, not a guessed PASS.
4. In the subsequent A3 decision, finalize exact target basenames and file-content contracts (including standalone switch vs grouped file), retained user data on uninstall versus explicit reset, version/backup retention, and migration precedence. Reject duplicate owners, shadow writable stores, format-conflicting aliases and ambiguous legacy data.
5. Only then implement B2 with exact-byte backup, stage/commit/readback, mount RW lease and independently verified RO, interrupted-write/power-loss/rollback negative fixtures, and separately approved target tests.

**Current disposition:** This graph is a reviewed *candidate inventory*, not an exhaustive proven consumer/rollback map. The active source-side persistent data paths and actual on-unit formats **have not changed**. The public QNX/source CI gate is evidence that this graph remains consistent with the checked-in source, not evidence of completed or safe migration.
