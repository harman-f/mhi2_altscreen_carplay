### Current installation and runtime limitations — separate incidents, not universal failures

- [#73](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/issues/73): Waze/Google Maps map centering wrong on Škoda VC; intermittent wireless music glitch; separate comment raises an intermittent call audio issue.
- [#70](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/issues/70) and [#69](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/issues/69): mixed previous-install/backup or `mm-ipod` failure reports; maintainers explicitly refuse overwriting unknown original file states; missing sound during calls is independently reported and unresolved. A participant reports that an **existing modified** MU1440 setup works after repairing its original wrapper, not a universal supported recovery procedure.
- [#71](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/issues/71): multiple `WMAPS_TRANSACTION_FAIL=INSUFFICIENT_HEADROOM` errors, especially MU1367/791; the complete space-check telemetry/previous-mod state differs. The maintainer advises **not disabling the space guard or deleting backups**. A third-party bypass recipe appears in comments but is not endorsed and should not be published as a fix.
- [#76](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/issues/76): 2017 VW Mk7.5, MU1367/P4521 with V3.2: **touch input stops** when OEM popup overlays wireless CarPlay; this is an author-reported regression, not directly evidenced on MU1440.
- [#75](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/issues/75): MU1367/AID791 right-hand-drive vehicle displaying left-hand-drive wireless orientation.
- [#79](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/issues/79): wireless remains functional but navigation/settings menu entry disappears on one user setup.

**Source availability (explicitly checked):** the [V3.2 release](https://github.com/omonob/VW-MHI2-Wireless-Carplay-Maps/releases/tag/v3.2) states that no separate complete implementation source archive or build tools are provided. GitHub includes installer scripts, partial public source and a tagged repository snapshot; **the complete native receiver and reproducible firmware-specific build chain are not available as an independently published package**. Do not falsely say “no source at all” or confuse the auto-generated “Source code (zip)” with a full receiver implementation. No new public source publication was found on 25 Nov.

**Compatibility of latest package:** MU1102/AID790+791, MU1367/AID790+791, Škoda MU1440/AID790 under exact native fingerprints. **MU1440/AID791 unsupported**, MU1433/MU1447 wired-only. The positive #73 report does not provide a specific cluster part and must not be conflated with an exact 790 hardware ID verification. V3.2 is still marked experimental.

## 2. Important follow-up release — tomasz MU1367

Credits **omonob as receiver/maps origin**, so it is a distinct firmware/vehicle integration and evidence set, not an independent protocol-receiver family and not a Škoda MU1440 port.
- [Experimental **MU1367-v1.6.3-e**](https://github.com/tomasz-twardzicki/MHI2-Carplay-Maps/releases/tag/MU1367-v1.6.3-e), **21 Nov**, adds complete OEM restore/fresh SD installation workflow, host and QNX shell regression; no fresh radio acceptance.
- **v1.6.6-e was withdrawn**, per the latest release notes, after reported Keep/disconnect failures, lag and head-unit freezes. Cause not confirmed. Never recommend that withdrawn build.
- [Latest experimental **MU1367-v1.6.7-e**](https://github.com/tomasz-twardzicki/MHI2-Carplay-Maps/releases/tag/MU1367-v1.6.7-e), **24 Nov**: restores proven parent/test2 runtime, opts out of the withdrawn shared BT/call/touch changes and adds an **optional reversible AID 790** package with safe area `202,16,606,344`. New MU1367/790 combined source/input and physical calls/touch/reconnect are **not yet vehicle accepted**. Stable 1.6.1 remains separate; neither release is a Škoda MU1440 port.
- Public [wireless-native/v161 C/Java integration](https://github.com/tomasz-twardzicki/MHI2-Carplay-Maps/tree/main/MU1367/wireless-native/v161/src) is useful for comparative research; it does not imply that omonob published all his receiver source.
